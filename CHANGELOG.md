# Changelog

## SCF 2026.3

Upstream restructured the workbook again, which broke the autopilot validation
gate (issue #4). The parser now reads 2026.1.1, 2026.2 and 2026.3 from one code path:

- **Risk/threat likelihood matrix.** The two per-control summary columns are gone;
  each control now rates every risk (65) and threat (45) as `Unlikely`, `Possible`
  or `Likely`. `controls[].risks` / `threats` keep their id-list shape and hold the
  ids rated `Possible` or `Likely`. New additive fields `risk_likelihood` and
  `threat_likelihood` carry every rating (`{id: rating}`). A rating outside that
  vocabulary fails the gate (`likelihood-value`).
- **Compensating controls moved inline.** The separate tab is gone; the same
  columns now sit on the control tab. Output shape is unchanged.
- Smaller header changes: `Documentation Artifact` is now `ERL Artifact`, the
  Organization Defined Parameters column became `Notes` (still emitted as
  `org_defined_parameters`), and the risk catalog gained an `Old Risk #` column.
- **Control ids were renumbered** (858 added, 801 removed, 1,457 marked
  `- renumbered`). Consumers must migrate stored 2026.2 ids; the workbook's
  `Legacy SCF #` column is the old→new map and is not emitted by this API yet
  (see the README migration note).
- The MON-03.3 evidence-request typo is fixed upstream, so its override is now
  scoped to 2026.1.1 and 2026.2.

renamed **Focal Documents**, and the compensating-controls **SCF Control #**
header was shortened to **SCF #**. Both broke the weekly autopilot (issues #1,

names, so one parser reads every supported release, and tab names are matched
with the same normalization column headers already got.

New this release: the **QTS** (Quantum Security) control family, threat **MT-28**
(mapped to nearly every control, which is why almost all controls show a
`threats` change), and 25 crosswalk frameworks — most of the churn is upstream
adding explicit year suffixes to framework names.

is no longer version-scoped (`mon-03.3-erl-typo`); the gate resolves it
automatically and will warn once upstream fixes it.

2026.1.1 — that archive has no 2026.2 to compare against. Parsing the 2026.1.1
workbook with this release still reproduces the committed 2026.1.1 dataset
byte-for-byte.
